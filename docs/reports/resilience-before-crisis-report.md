# Resilience Before Crisis

## Research Question

How should ROUTE explain flood, wildfire, snow/ice, port disruption, mountain
closures, incidents, and evacuation as fundable obligations without claiming
hazard proof or recovery performance?

## Decision This Supports

This report supports the communications decision to make resilience a service
design obligation, not an emergency afterthought.

## Executive Thesis

The country should not discover its freight backup plan during the disruption.

Interstate 2.0 should ask resilience questions before crisis:

```text
which promise depends on this node?
  -> what happens if it fails?
  -> what alternate route or hub absorbs pressure?
  -> what recovery target is credible?
  -> what evidence is missing?
```

## Findings

### ROUTE-RES-01 - Resilience is part of the service promise.

**Observed constraint:** T1 reliability depends on alternates, relay nodes,
interchanges, closure scenarios, and recovery assumptions.

**Implication:** Resilience should be communicated as a planned obligation, not
as a vague benefit.

**Confidence:** High for doctrine; heuristic for outcomes.

### ROUTE-RES-02 - Alternate routes matter only when they preserve service.

**Observed constraint:** Current materials distinguish map existence from
service evidence.

**Implication:** Do not say an alternate exists unless capacity, contact,
recovery, and scenario assumptions are named.

**Confidence:** Medium-high.

### ROUTE-RES-03 - High-leverage nodes are candidates, not proof.

**Observed constraint:** T1/T1 diamonds, mountain passes, ports, and interchange
fixes are useful proof targets, but site geometry and recovery validation remain
gated.

**Implication:** Use them as evidence campaigns and pilot candidates, not as
construction-ready packages.

**Confidence:** High for boundary.

### ROUTE-RES-04 - Hazard scenarios make resilience fundable.

**Observed constraint:** Scenarios can translate disruption into recovery
targets and evidence asks, but current hazard proof is not complete.

**Implication:** Funders can be asked to support scenario libraries and source
packs before hardening claims are promoted.

**Confidence:** Medium.

## Resilience Obligation Frame

| Stressor | Question To Ask | Evidence Gate |
|---|---|---|
| Flood | Which service promises lose usable capacity? | Hazard source, exposure, alternate capacity, recovery assumption. |
| Wildfire | Which routes, hubs, or communities need preplanned alternatives? | Scenario evidence, closure duration, reroute feasibility. |
| Snow/ice and mountain closure | Which national or regional promises depend on a constrained pass? | Closure history, route capacity, service impact, recovery target. |
| Port or border disruption | Where does freight stage or reroute without breaking service? | Terminal access proof, staging capacity, operator review. |
| Interchange incident | Which T1/T1 or T1/T2 contacts create national fragility? | Geometry review, incident scenario, throughput/recovery evidence. |
| Evacuation or emergency access | Which lower-tier routes must remain visible? | Local/state review, access obligation, scenario scope. |

## Safe Language

| Use This | Avoid This |
|---|---|
| "Resilience is a service-design obligation." | "The network is crisis-proof." |
| "Scenarios can show what evidence a hardening package needs." | "This hardening package is justified now." |
| "Alternate routes need capacity and recovery evidence." | "A line on the map is a backup plan." |
| "T1/T1 nodes are proof targets." | "Specific interchanges have proven benefit." |

## Evidence Needed To Promote The Claim

| Evidence Need | Why It Matters |
|---|---|
| Scenario library | Defines the disruption being tested. |
| Hazard and closure sources | Prevents generic resilience language from becoming proof. |
| Alternate-route capacity | Shows whether service can actually absorb pressure. |
| Recovery target | Makes resilience measurable without inventing outcomes. |
| Site and state review | Keeps delivery, right-of-way, safety, and maintenance constraints visible. |

## Recommendations

### Adopt Now

| Recommendation | Owner | Validation |
|---|---|---|
| Use "resilience before crisis" as the public frame. | communications owner | Decks avoid proof or hardening overclaim. |
| Treat resilience packages as scenario-backed candidates. | Traffic Engineer / State DOT Planner | Each package names stressor, evidence, and review need. |
| Tie resilience to T1/T2/T3/T4 service roles. | research owner | Claims state which promise or access obligation is affected. |

### Reject Or Defer

| Claim / Action | Reason |
|---|---|
| Claiming crisis-proof national service. | Hazard, capacity, and recovery proof are not closed. |
| Claiming a specific flyover or hardening project is justified. | Site, cost, demand, delivery, and recovery evidence are not closed. |
| Treating maps as alternate-route proof. | Map validity is not service or recovery proof. |

## Non-Goals

- This report does not model hazards, recovery time, throughput, or closures.
- This report does not select hardening projects or construction designs.
- This report does not claim evacuation, emergency, or freight continuity
  guarantees.

## Gate

Decision: pass_with_risk

Rationale: Resilience is ready as a story-ready Interstate 2.0 obligation and
candidate funding lane. Hazard, recovery, alternate-capacity, site-specific,
construction, and benefit claims remain gated.
